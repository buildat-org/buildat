Starport: the server list and the Starport ID
=============================================
apps/starport is a public server list and an optional login, the Starport
ID. Both are opt-in, and Starport is an app like the others, so anyone can
run their own. The official one is https://starport.buildat.org.

- A server is listed only if its admin names a Starport in
  `starport.json`. Its announce carries its address, app and player count,
  not who is playing. Its kind (world, arena, app, other) is the
  file's, or else the app's own: `main/meta.json`'s "kind", experiment
  and check listed as other ([APP_CATEGORY]).
  A listing not announced for 30 days is dropped -- a claimed one after
  a year, while the account that claimed it exists and is not suspended
  or banned -- unless moderation has a record of it; its server, back, is
  listed again under a new id and claim code.
- A server accepts Starport IDs only if its admin turns them on; local
  accounts work without one. A player uses an ID only by choosing "Sign in
  with your Starport ID". After that the client signs in with the ID by
  itself on the next joins to that server, a new token each time, until the
  player logs out there or logs in with a password. The client keeps that
  mark itself, out of the server's reach (not on the web client).
- Each community sees a different identifier for the same ID, and a
  display name the player picks for that community.
- The client asks before it contacts a host, a Starport included. Its
  Starport settings say which Starports it uses; with none left there, it
  uses none.
- A token is made only for a verified listing that is not banned: an
  announce naming another server's address never verifies.
- On the web the ID signs in on the Starport's own page, `/authorize`,
  in a window of its own; the token goes to the opener by postMessage,
  only to the listing's own origin or one in `web_clients`. `/id` is
  the ID's page: its sessions and last 20 logins with "Log out everywhere
  else", TOTP, the e-mail, the password and the age, and making an ID.
  The age asks "18 or over?" first, the birth year only on a No, kept
  until the ID turns 18. With TOTP on, changing the password or the
  e-mail takes a current code.
- A website signs its visitors in the same way ([STARPORT_SITE_LOGIN]):
  its operator registers it (the Starport app's Sites page: a name and
  an origin, https://host[:port]) and gets an id and a secret. The site
  opens `https://<starport>/authorize?site=<id>` with `window.open`; the
  visitor logs in there and allows, and the site's window gets
  `{buildat_starport_token, name, site}` by postMessage, to the site's
  origin only. The token is `<payload>.<hmac>`: payload the base64url
  (no padding) of `{"v": 1, "typ": "site", "iss", "aud", "site", "sub",
  "name", "exp"}` (aud and site the site's id, iss the Starport's name),
  hmac the hex of HMAC-SHA256 over `buildat-token-1\n` and the payload's
  text with the secret's bytes (the secret is hex). The site's server
  checks the hmac, v, typ, the site id and `exp` (a unix time), and
  knows the visitor by `sub`, which is the
  same on every visit and different on any other site, server or
  fleet; the name is one the visitor picks for the site. A new secret
  makes the old tokens fail. A server's token is the same with typ
  "server" and listing in place of site, and a server takes no other
  typ. A sub is per listing or fleet: a server that joins or leaves a
  fleet sees its players under new subs, and their accounts there under
  the old ones are left behind.
- A Starport ID holds a name, a password hash and, if given, a recovery
  e-mail. It is deleted from its own settings. Mail goes through the
  server's SMTP server, set on the Server window's Health page; the old
  `smtp` setting moves there at the first start that has none.
  A session lasts 30 days from its last use. Wrong logins are limited
  by the network they come from (an IPv4 /24, an IPv6 /64), 30 an hour,
  never by the name tried; new IDs to 5 a day from one network.
- The address a login or a report came from is kept for `retention_days`,
  7 by default, which the Starport's admin sets; a daily pass then clears
  it. The ID sees its own recent logins with their addresses until then.
- The admin's Settings page holds every setting, each as JSON, a setting
  newer than the Starport's first start at its default. `web_clients`
  lists the origins of web pages besides a listed server's own that
  `/authorize` sends a Starport ID's token to: a page that serves the web
  client with no game of its own, as `apps/play` does
  (`https://play.buildat.org`), is listed there to let its players sign
  in with an ID.
- `/` is a read-only page ([FRONT_PAGES]): the listings by fleet with
  kind and audience filters, the transparency numbers and a privacy
  line; only what suits a teen (no yes to sexual content, drugs or
  gambling, no unmoderated chat or content, no open report, no adult
  audience) and claimed at least `page_delay` (3600 s) ago, the busiest
  first. The web client is at /index.html.
- Reports, their weights, the queue, decisions, statements of reasons and
  appeals are builtin/moderation's (doc/server_api.txt); a statement has
  one appeal; a decided one closes it. A blocklist takes only an offered listing or fleet; an
  account makes 20 at most, none when banned. Moderators are accounts at
  the Steward level ([TRUST_LADDER]), set by the "level" request as
  Hearth's are.
- `recommended_hearth` (an http(s) address) and `recommended_aittas` (a
  list of them) come to clients in `/api/v1/list` and an ID's "me". A
  logged-in ID's line in the launcher's overlay gets "Discuss", which
  joins that Hearth; it is also the home Hearth of a package whose
  manifest names none. Aittas the client has on neither its list nor its
  ignored list are offered in one dialog on the launcher's screen, never
  under the PIN or the managed file; what is not added is ignored, and
  the client's Starport settings list both.
- A new client version ([VERSION_CHECK]): an executable the admin puts at
  `<user>/apps/starport/version_adapter` -- a file, never a setting, so
  that an admin's web login cannot run commands -- is run at the start
  and hourly, given 60 s, and prints one JSON object:
  `{"version": "0.6.90", "url": "https://...", "platforms": {"linux":
  {"url": ...}, "win64": {"url": ...}}}`. `/api/v1/list` carries it as
  "version", https links only; a failed run keeps the last good answer
  and logs why. `util/starport_version_github.py` is the one for GitHub
  releases. A native client newer than its own shows a notice on the
  launcher's screen with its platform's link, "Download" and "Not
  now", which is kept until a newer version. Once Download has opened
  the link, the notice says what to do next by the file's name (an .exe
  is run, an archive extracted; the saves and settings stay in the user
  directory) and offers "Close Buildat", out of the installer's way.
- `play_url` (`https://play.buildat.org`; "" for none) is a play page:
  a server serving the web client with no game of its own. The page at /
  links each TLS server to `<play_url>/?server=host:port`; the page joins
  it if a Starport in its own settings lists that address, with TLS on
  an https page, and otherwise stays on the launcher and says why.
  `/api/v1/list` and the answer to an announce carry it as "play"; a listed
  server lets that page's WebSocket in while the Starport lists it, and
  `/authorize` takes its origin as if it were in `web_clients`.
- The HTTP API is under `/api/v1/`; a path without `/v1/` answers
  `{"ok": false, "code": "upgrade_required", ...}`. A refusal is `{"ok":
  false, "code": ..., "error": ...}`: code for a program to match
  ("refused", "too_often", "no_listing", "session"), error for a person.
  A newer server's announce is taken: a kind this Starport does not know
  is listed as "other", an audience as "adult", a descriptor's value as
  "unknown"; an access or login word is listed as it is, and a client
  that does not know it leaves the listing out. The announce's keys this
  does not read (4 KB at most) are passed on in `/api/v1/list`.
