Kit API 1: the surface a game's scripts reach
=============================================
[KIT_API_1] Every name and value of Kit that a game made with Kit API 1
can depend on: the server's c, its handlers and type-table fields, a type
file's environment, a client part's handlers, e and kit table, a
movement's declaration, w, s and i, every builtin type's parameters
(kind, default, range, choices), inputs, outputs, state and handlers,
the reserved names, the prefabs, items, sounds and voxels Kit ships, and
the format and API levels. builtin/kit/api.h ("What Kit API 1
promises") says what the promise is; this file is its inventory.

The listing at the end is made from the code by
`util/api_names.py --kit-write`: the box's own Lua (box.c's PRELUDE, run
under luajit) defines the builtin types as a server does, and the rest
is read from box.c, kit.cpp, client_lua/ and src/interface/aitta.h.
util/kit_api1_surface_check.sh (`util/api_names.py --kit-check`)
compares the code with it.

"reserved text {<word>:...}": in a text a client draws, {<word>:...} is
Kit's ([KIT_TEXT_PLACEHOLDER], api.h's "A text's placeholders"): the
words listed after it have a meaning, any other is drawn as written and
warned of, and a later Kit may give it one.

Each line is "<key>" or "<key> | <value>". A value ending in
[experimental] or [internal] is outside the promise: it may change or go
in any release (kit.cpp's experimental_names(), a type's
`experimental = true`).

What the check lets through
---------------------------
- An addition passes: within Kit API 1 Kit only adds. The check says to
  regenerate the listing.
- A removed key fails, unless a deprecation below covers it.
- A builtin type's parameter that is removed or renamed, or whose kind
  or default changes, or whose range or choices narrow, fails unless the
  type's version is raised and it has a migrate(params, from) that takes
  an old instance forward. The check runs that migrate in the box from
  the listed version:
  - a removed or renamed parameter: migrate of {name = its old default}
    no longer has the name;
  - a changed default: migrate of {} gives the old default (an instance
    that never set it plays as before);
  - a changed kind: migrate of {name = its old default} changes the value;
  - a narrowed range or choices: the raised version and a migrate are
    enough (the check does not run it on a value).
- An input's or output's value type that changes fails. A type's version
  or a format level that goes down fails.
- Any other change (a signature, a type's handlers, a state key's flags)
  passes; regenerate.

Deprecations
------------
A line "deprecated: <key> | <level> | <what to use instead>" below
records a name on its way out. Until Kit's API level (KIT_API,
src/interface/aitta.h) reaches <level>, the name stays as an alias of
its replacement; from that level on, it may be removed or changed, and
the check lets it.

deprecated: reserved type kit/world | 2 | kit/terrain
deprecated: reserved type kit/world_region | 2 | kit/terrain_region
  ([KIT_WORLD_RENAME]) a composition, prefab or save naming the old type
  reads as the new.
