Hearth: a community forum as an app
===================================
apps/hearth is a buildat app:
topics, threads under them and messages in those, each at a permanent
address. It is read as plain HTML in a browser and taken part in from
the buildat client.

Running it
----------
    bin/buildat_server -m ../apps/hearth -D <user path> -P <port>

The server serves both faces on its one port: the game protocol to the
client, and HTTP to a browser. The app itself is main/ (main.cpp on the
server, client_lua/init.lua sent to the client and run there through
"client_main" in main/meta.json). It needs the builtins network, client_lua, client_data,
storage and accounts.

The data
--------
One SQLite file, <user path>/apps/hearth/hearth.sqlite (WAL; the
directory is the app's id, "<author>.<name>" for an installed release),
made on the first start; a file from before a column gets it added. Tables:
topics (a parent topic, 0 at the top), threads, messages, edits (what
an edit replaced, when and by whom), follows, notifications, members
(when an account first came), reads (the threads an account has
opened), topic_reads, thanks, reports, release_threads, and search, an
FTS5 index over every message (a thread's title on its first message).
Every statement binds its values.

A thread's subject ([PACKAGE_SUBJECT]) is a package's "author/name" and
key, "server:<host>:<port>" or "game:<source>". A package's threads are its
place, /p/<author>/<name> (a second key under the name noted); a thread
about no package is linked to one afterwards ("About a package..."; the
link command) by whoever started it or a moderator, only to a package
with a release here. A thread about an app or a ContentDB game lists up
to three servers its Starports list running it that their play page can
join, most players first ([HEARTH_VISITOR_FLOW]).

Releases: the admin's release_sources names the Aittas to read and this
Hearth's own addresses; a poller reads each Aitta's list once a minute,
and a release whose home_hearth is one of the addresses becomes a thread
in the "Releases" topic by "author (Aitta)", with its description and
changelog. Its thread lists the problems marked fixed in its version
(same package and key), whose reporters and followers are told it is
out.

Accounts and admins
-------------------
Joining is builtin/accounts: a local account or a Starport ID, as the
server's admin set up its logins. A server with no admin logs "setup
code <code>"; whoever joins with it is the admin. The server's admins
are Hearth's admins; the admin makes moderators, and a moderator
helpers (Limits, below). Nothing is posted without joining; the HTML
face needs no account.

The HTML face
-------------
Claimed from builtin/network (claim_http_path); /app (also /play and
/index.html) and the rest stay the web client's.

    /                the topics (one level of subtopics) and the latest
                     20 threads
    /topic/<id>      a topic's threads, answered ones first, then by the
                     latest message, 200 at most
    /topic/<id>/atom its Atom feed ([HEARTH_DEVLOG]), linked from the
                     topic's page: its 20 newest threads, newest first,
                     each its first message as HTML as the thread's
                     page renders it; visible threads by an account
                     that is not banned; the links' base as
                     /api/v1/discussed's; Cache-Control max-age=300
    /t/<id>          a thread: the question, the reply that answered it,
                     then the rest in order; every message at #m<id>;
                     in parts of 256 kB of bodies, ?after=<id> the next
    /m/<id>          one message and a link to it in its thread
    /search?q=...    50 best matches, titles weighed 5 to a body's 1, an
                     answer counted twice
    /p/<a>/<name>    a package's place: the threads about it
    /u/<name>        an account's page
    /f/<id>[/<name>] an uploaded file (below); the name is only what a
                     browser saves it as; /f/<id>/thumb an image's
                     thumbnail
    /brand/<file>    the pages' font and logo ([HTML_BRAND])
    /robots.txt      keeps crawlers off /f/

Each page's foot links to the web client, "in the browser"
([HEARTH_OPEN_HERE]): from a topic's, a thread's, a message's, a
package's (/p/<author>/<name>) or an account's (/u/<name>) page as
/app#open=<that page's path>. The web page takes only that shape
(/topic, /t, /m, /p or /u and up to 200 of [A-Za-z0-9_.-/]) into the
client's BUILDAT_OPEN, and Hearth opens that page after the join, over
home: Back goes home, and a place not there is said on home. A reload of
the page leaves #open out, so the page the user was on comes back
instead ([WEB_RELOAD_APPS]: the web client loads again by itself when a
phone's browser dropped its connection in the background). The native
client is not reached by these links.

A topic's or a thread's name has a cyan blob after it when it was
written in within a day (●) or a smaller one within a week (•); a
topic's counts its subtopics' threads ([HEARTH_BLOBS]).

Anything else under those paths is a 404; a POST is a 404. A message is
CommonMark with GitHub's tables, strikethrough, task lists and URL
autolinks, and ||spoilers|| (interface::markup::to_html, md4c); a single
newline breaks the line (<br>, as GitHub's comments do): raw HTML is
text, a link or an image to anything but http, https, mailto or a
relative path is its text alone, an image is a link to it and never
loaded but for the Hearth's own /f/<id> (an <img>, lazily loaded), and
every link is rel="nofollow ugc". "#1234" links to thread 1234, "@name"
to /u/name. An uploaded image's thumbnail (320x240 at most) goes at the
message's end linked to the image, and a message's files are listed
under it. A message shows its thanks count. A search's words are each
quoted, so nothing typed is FTS5's query language; the last word is a
prefix. A hidden message shows "Hidden by a moderator: <statement>" and
not its text; a thread whose first message is hidden is hidden with it,
title too, and gone from the portal, its topic and search.

/api/v1/discussed is for another site's "Discussed today" line (the
project's front page): JSON {span: "today" | "this week" | "this month",
message: {id, author, created, excerpt, url, thread: {id, title, url},
topic: {id, name, url}}}, or {} when a month has fewer than two to pick
from. The span is the shortest of 24 hours, 7 days and 30 days with two
or more messages that are visible, in a visible thread, not empty as
text, and by a member that is not banned; one of them at random, kept
ten minutes. The excerpt is plain text (the markup taken out, a link
as its text, a spoiler "[spoiler]"), about 200 characters cut on a
word; put it in a page as text, never as HTML. Answered with
"Access-Control-Allow-Origin: *", under the pages' rate. The links are
absolute: their base is the admin's public address, set from the client
with {"cmd":"public_url","url":"https://forum.example.org"} ("" to
clear), or else the request's Host over https (http for 127.0.0.1 and
localhost).

/api/v1/feed is for a launcher's "now" strip and an app's page
([LIVELY_MENU]; the client reads it from the Hearth in its Starport
settings): JSON {url, announcements, active, packages}, a thread {id,
title, posts, last}, read at url + "/t/" + id. announcements are up to 3
threads of the topics of category "announcements" (topic_category, by a
moderator; their subtopics too) written in within 30 days, the latest
first; active up to 5 others with the most messages of the last 7 days;
packages "author/name" -> {posts, last, threads: its 3 latest}, the 300
packages written about last (every key's together, as /p/). Only visible
threads started by a member that is not banned, or a release's thread;
posts counts the visible messages; a title is plain text. Kept a
minute, a hide or a category's change drops it; CORS and the pages' rate
as /api/v1/discussed, the same base url. A launcher's click on a thread
joins the Hearth and opens it, as BUILDAT_OPEN does (the client's
hearth_open()).

Taking part: the client
-----------------------
The client ([HEARTH_UI]) is a sidebar of topics beside a page, one
scroll view, by the arrow keys between the two; Escape at the top opens
My account -- from a launcher, "Exit to launcher?" (Exit, My account,
Cancel), which the × at the frame's top right opens too ([HEARTH_CLOSE]);
on the web "Leave Hearth?" (Leave, My account, Cancel), Leave going back
to the page before with the login kept ([HEARTH_WEB_BACK]) -- and on the
web Back steps through the pages to the sidebar and that dialog; a draft
and the
place kept over a restart ([HEARTH_RESUME]). A thread or topic row carries
a ● for a message within a day and a • within a week, amber while
unread ([HEARTH_NEW_MARKS]); home's "Waiting for you" lists the unread
threads, followed first. The client's pages: the topics and the latest
threads, a topic (its
threads, and a new thread's title and first message), a thread (its
messages, a reply, Follow, "This answered it", Report or Appeal),
notifications, and for an admin the moderation queue and a new topic
(a name, what it is about, and a parent: none, or a top-level topic --
subtopics are one level deep). The client draws a message from the
server's HTML of it (a thread's "html"; [HEARTH_LINES_CODE]): its text
with a link's address after it, a fenced block in the mono font on a
darker ground (a line past the width cut with "..."), a picture of the
Hearth's own under the text rather than its Markdown. A message's field
is multi-line: Enter breaks the line, Ctrl+Enter sends; Bold, List, Link,
Image and "Code block" put their Markdown in at the cursor, and Preview
shows the message as the HTML face will. A member thanks a message
("+N" at its top right; the author told once while unseen).

Each action is a packet "hr:req", JSON {id, cmd, ...}, answered by
"hr:res" {id, ok, result | error}. The commands and who may use them:

    me                     who this is: account, admin, moderator,
                           helper, unseen, level, open_reports (a helper
                           and up)
    topics, topic, thread  read; "thread" with after=<id> gives the
                           messages after it, 1000 a call
    message                message=<id>: its thread's id (a hidden
                           thread's to a moderator and its author only)
    subject                subject=<text>: its threads; a package's
                           name alone, every key's ([HEARTH_OPEN_HERE])
    search                 30 a minute per account
    preview                body: the HTML face's rendering of it
    following              the threads followed, the unread first
    mark_read              topic (and its subtopics), or 0 for all
    subjects               the packages with a release here
    link                   thread, subject: one of those, by the thread's
                           starter or a moderator
    thank                  a member: message, on; 60 an hour, not one's
                           own; the count back
    upload                 name, data in hex -> {id, image} (Files)
    thumb                  file -> {type, data in hex}: its thumbnail
    new_topic              a moderator; name, about, parent (0, or a
                           top-level topic)
    edit_topic             a moderator: topic, name, about
    new_thread             anyone (a moderator in a topic marked by
                           topic_mod_threads); topic, title, body, subject, kind
                           ("", question, problem, idea, or patch in a
                           tracker topic), version; or server=true and
                           subject "server:<host>:<port>", in the topic
                           of category "servers" (made "Servers" when
                           none is) -- the client's Discuss
                           ([DISCUSS_SERVER]); or game=true and subject
                           "game:<source>", in category "games"
                           ([OVERLAY_DISCUSS])
    status                 a moderator: a problem's (open, confirmed,
                           fixed, wontfix) or a patch's (open, applied,
                           wontfix), fixed_in a version
    topic_tracker          a moderator: topic, on -- its threads are tickets
    topic_category         a moderator: topic, category ("servers",
                           "announcements" or "")
    topic_mod_threads      a moderator: topic, on -- only a moderator
                           starts its threads (a devlog), replies stay
                           open to all; the topic's own mark, its
                           subtopics have theirs ([HEARTH_DEVLOG])
    tracker_link           a ticket's starter or a moderator: thread, link
                           ("" takes it off); below
    tracker_domains        the list; a moderator: add, remove (domains)
    reply                  anyone; not in a hidden thread but a moderator
    edit                   the message's author or a moderator
    answered               whoever started the thread, or a moderator;
                           message 0 takes it back; not the first message
    follow                 on true or false
    notifications          the latest 50; they are seen after
    report                 someone else's shown message, with a reason
    appeal                 one's own message a moderator hid or
                           deleted, with a text
    queue                  a helper and up: the open reports, appeals,
                           tracker domains and held links
    moderate               a moderator: a report hidden or dismissed, an
                           appeal restored or dismissed, a tracker
                           domain accepted or dismissed; a hide and an
                           appeal's dismissal need a statement, which its
                           author is notified with. A helper too: a held
                           link approved (shown, its author trusted) or
                           rejected (deleted)
    delete                 a moderator: message, thread (true: the whole
                           thread; so is its first message's), reason,
                           text -- deleted for all but the moderators and
                           its author, its place saying "Deleted by" with
                           the reason; the author notified, may appeal,
                           restored by the appeal's restore; purged with
                           the files only it used after 183 days. Not the
                           admin's message ([HEARTH_MOD_TOOLS])
    ban                    a moderator: name, days (0: until lifted),
                           reason, text, delete_days (their messages of
                           those days deleted as delete does) --
                           builtin/accounts' ban with its end and why,
                           said when the join is refused; it lifts itself
                           at the end. Not a helper or above
    vet_file               a helper and up: file or message (each of its
                           new account's images), on -- shown to
                           everyone, or taken back; only an author's
                           below one's own level
    trust                  a helper and up: name, on -- an account
                           trusted (a member), or no longer; a helper
                           takes back only its own, within 7 days
    level                  name, level (a number): one below the asker's
                           own, from a moderator -- a moderator makes
                           helpers, the admin moderators
    staff                  a helper and up: name and level of each
                           helper and up
    public_url, file_settings, delete_file, release_sources
                           the admin's; described where they belong
    account                name: its level, its messages; to its owner
                           its trust counts; to a helper and up who
                           trusted it and whom it trusted

Pushed by the server: "hr:new" {thread, message} to every client that
has that thread open (a chat runs on it), and "hr:notify" {unseen} to
an account that was notified. A notification is a reply in a followed
thread (one follows what one started or wrote in), an @name mention, a
message marked the answer, a hide, a restore or a refused appeal.

The client has no page to edit a message or search: those are requests
only (a scripted client's, below), and search is the HTML face's.

Tickets
-------
A topic the admin marks a tracker holds tickets: problems and patches,
each with its status, its id the thread's #1234. A ticket has one
tracker link -- a branch, a pull request, an issue elsewhere, http(s)
only -- shown above the discussion ("Tracker:" on its page), set by
whoever started it or the admin.

Hearth keeps a list of tracker domains (exact host names). A link to a
listed domain is shown. A link to another is shown when whoever set it
may post links now (a member or up, looked up when it is shown),
and setting it adds its domain to the list; a new account's waits in
the moderation queue as a domain, and accepting it adds the domain.
Removing a domain hides every new account's link to it; a moderator
also takes a single link off. A new account's links in a message are
allowed to the listed domains and to Hearth's own pages; one elsewhere
is held: the message (a new thread with it) is shown to its author
alone, "Waiting for a helper to approve its link", and queued. One
account has one held at a time. Approved, it is shown and its author
trusted; rejected, it is deleted.

A patch is a file named .patch or .diff of text whose first 10 lines
have "From ", "diff --git ", "--- ", "+++ " or "@@ " at a line's start,
10,000 lines at most. Anyone uploads one, a new account too; it is
served as text/plain, so it is applied as it is fetched (git am), and a
message linking to it shows it inline below the message, 256 kB of
patches a message at most, on both faces.

Files
-----
File... under a message's field picks a file (the browser's picker; on
native the client's list of <user>/exports) and uploads it as the
request "upload" {name, data in hex}; its link goes in at the cursor,
![name](/f/<id>/name) for an image. A file is 16 MiB at most, 20 an hour
(an admin any number). A new account uploads a patch (Tickets, above)
or an image, one a thread; a below-member's image is drawn only for
helpers until one shows it to everyone (vet_file) or its account becomes
a member ([HEARTH_NEW_IMAGES]). A PNG or JPEG is
read (stb_image, those two only, 40 million pixels at most) and written
again within 1920x1080 (the short side 1080), a JPEG at quality 85:
nothing else of the upload is kept, its metadata with it. Any other
file is kept as it came and served as application/octet-stream.

A file's id is random (under 2^46), and /f/ refuses a file all of whose
messages are hidden, held or in a hidden thread ([SEC_HEARTH_FILES]).
A file's use is a fetch of /f/<id>, which robots.txt asks crawlers not
to make. The admin's request "file_settings" {budget, lod2_after,
delete_after} (bytes and seconds; 1 GiB, 182 and 365 days) says what is
kept: once an hour, while the files take more than the budget, the
longest unused go first -- an image unused for lod2_after is written
again within 960x540 (a JPEG at 60), any other file is deleted then, an
image unused for delete_after is deleted -- until they are under it.
"delete_file" {file} deletes one at once (an upheld claim of copyright
or personal data); the admin has no page for either yet.

Limits
------
A title is 200 bytes at most, a message 20000, a topic's name 80; no
control characters but a tab, and a line break where lines are allowed.
A level is worked out at each post. Accounts saves it as the number;
the names shown (Guest, Resident, Keeper, Steward, Host) are
accounts::level_name()'s and accounts.lua's LEVEL_NAMES, changed
together:

    0  a new account (Guest): 2 threads a day, 10 messages an hour, links to
       the tracker domains only (others held, above)
   10  a member (Resident): trusted, and none of its messages hidden by a
       moderator in the last 30 days: 10 threads a day, 60 messages an
       hour. Trusted is level 10 in accounts: by 5 active days -- a
       day (UTC) is active if the account read a thread or wrote a
       message that stands on it, and counts once it is over, so more
       on one day is no more trust -- or by a helper's or a
       moderator's approval
   20  a helper (Keeper), made by a moderator: 20 threads a day, 120 messages an
       hour; sees the queue, approves or rejects held links and trusts
       accounts, 20 a day; nothing else of a moderator's
   30  a moderator (Steward), made by the admin: no limit; the queue,
       the topics, the tracker domains, a file deleted, helpers made
       and unmade; the Server window's Accounts page (kick, ban,
       invites, levels below its own, Starport IDs let in)
   40  the admin (Host): a moderator's, and what is server-wide -- the files'
       settings, the release sources, moderators made and unmade

The levels are spaced so one added later goes between two. An edit
counts as a message. A link is "://", "www." or anything the markup
makes a link of. An account reports 10 a day at most (a moderator any
number), and has one open report or appeal per message.

A report weighs by its reporter's level: a new account 0, a member 1, a
helper and up 3, and nothing for 30 days after a moderator dismissed a
message hidden by reports it made. The reports of one network (an IPv4
/24 or an IPv6 /64) count once, at the highest. At 3 in all the message
is hidden, "Reported; hidden until a moderator looks", unless its author
is a helper or up; the moderator hides it (with a statement) or
dismisses the report, which shows it again. Search on the HTML face is
30 a minute per address (429 after), and every page 120 a minute per
address.

The environment
---------------
Hearth has no settings file of its own. Its variables are read by the
client, for a scripted client (a check):

    BUILDAT_HEARTH_NAME       join as this account (accounts.lua, as every
    BUILDAT_HEARTH_PASSWORD   <env>_ variable here); no default: the join
    BUILDAT_HEARTH_CODE       dialog. CODE is the setup code or an invite
    BUILDAT_HEARTH_TOTP       code, TOTP an authenticator's code
    BUILDAT_HEARTH_KEEP       1: keep the login on this client
    BUILDAT_HEARTH_STARPORT   join with this Starport ID token instead
    BUILDAT_HEARTH_ADMIN      admin requests after the join, a line each,
                              "cmd name [arg]" (e.g. "add bob bobpass1234")
    BUILDAT_HEARTH_REQS       Hearth requests after the join, JSON a line
                              each, numbered from 1001; every answer is
                              logged "hr: <json>" and every "hr:notify"
                              "hr notify: <json>". Default empty
    BUILDAT_HEARTH_OPEN       a thread's id[#<message id>]: open it after
                              the join instead of the topics. Default unset
    BUILDAT_OPEN              a web page's path, as the web client sets it
                              from #open= (above). Default unset

The check
---------
    apps/hearth/check.sh

Needs a built tree (Build/bin) and curl; about a minute. It starts a
server on port 29881 in a temporary directory, takes the setup code from
its log and drives clients with the variables above: posting, editing
and refusals, an answer, a mention and notifications, a chat line
within two seconds, every HTML page with escaped and hostile markup, a
new account's limits, a report, a hide with a statement, an appeal and
a restore, both search limits, the multi-line reply field, files
crushed, served and swept, and a tracker: a new account's patch shown
inline and applied with git am, its links and its tracker link by the
domains.
